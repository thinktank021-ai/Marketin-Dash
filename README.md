## 🌟 معرفی پروژه

این سیستم یک داشبورد مدرن، واکنش‌گرا (Responsive) و کاملاً راست‌چین (RTL) با فونت استاندارد **Vazirmatn** است که برای رصد لحظه‌ای ورودی‌های بازاریابی، تفکیک تماس‌ها بر اساس کارشناس، کانال و مقصد، محاسبه شاخص‌های مالی (CPL و CAC)، مانیتورینگ کمپین‌های گوگل ادز، تحلیل داینامیک فرصت‌های سئو در سرچ کنسول و ارسال گزارش‌های خودکار تلگرام توسعه یافته است.

### اصول بنیادی محصول (Non-negotiable Rules):
- **عدم صفرسازی در خطای اتصال (Anti-Zeroing):** در صورت قطع ارتباط با منابع خارجی (Google Sheets یا Google Ads)، هرگز اعداد داشبورد صفر نمی‌شوند؛ بلکه آخرین وضعیت معتبر با برچسب هشدار (Stale) نمایش داده می‌شود.
- **ایزوله‌سازی کامل برندها (Multi-Brand Isolation):** تمام داده‌ها، تنظیمات، بودجه‌ها و توکن‌ها بر اساس `brandId` جدا شده و هیچ داده‌ای میان دفاتر نشت نمی‌کند.
- **تفکیک داده‌های مالی:** مقدار هزینه ثبت‌نشده با صفر واقعی کاملاً متمایز است تا میانگین‌های مالی دچار اعوجاج نشوند.

## 🚀 ویژگی‌ها و قابلیت‌های کلیدی

- **داشبورد تحلیلی یکپارچه:** شمارش لیدها، تماس‌ها، نرخ تبدیل، تفکیک کانال‌های تبلیغاتی (گوگل ادز، اینستاگرام، پیامک، ارگانیک و ...) و تفکیک عملکرد کارشناسان.
- **تقویم شمسی پیشرفته:** انتخاب بازه‌های تاریخی منعطف در تقویم ۷ ستونه هجری شمسی با محاسبه مقایسه‌ای نسبت به دوره قبل.
- **اتصال Google Sheets:** خواندن زنده فایل‌های اکسل/شیت، کشف خودکار ماه‌ها و تب‌ها، با کش هوشمند و مکانیزم نجات از قطعی.
- **ماژول Google Ads:** گزارش زنده ایمپرشن، کلیک، هزینه (تبدیل لیر به تومان بر اساس نرخ ماهانه)، CPL و هشدارهای سیاستی و بودجه محدود کمپین.
- **مرکز تحلیل سئو و Search Console:**
  - نمودارها و جداول مقایسه‌ای با قابلیت مرتب‌سازی، فیلتر و خروجی CSV.
  - رادار فرصت‌های سئو (Opportunity Radar) با تحلیل تفکیکی کلیک بالقوه و شکاف CTR.
  - موتور داینامیک شناسایی فرصت‌های کم‌ریسک محتوایی و لینک‌سازی داخلی متناسب با حجم داده هر سایت.
- **سیستم استخراج شماره تماس (Phone Extraction):** نرمال‌سازی و تفکیک شماره‌های ثبت‌شده با فیلتر وضعیت قرارداد و خروجی CSV.
- **ربات تلگرام (Telegram Bot):** ارسال گزارش‌های لحظه‌ای، پایان‌روز (ساعت ۱۸:۳۰) و روزهای پنجشنبه (ساعت ۱۴:۴۰) با تقویم تعطیلات رسمی ایران.
- **پشتیبانی PWA:** عملکرد پایدار در موبایل، ثبت Service Worker و حالت کش آفلاین.
- **احراز هویت دومرحله‌ای ایمن:** سشن‌های ۲۰ دقیقه‌ای با الگوریتم رمزنگاری `scrypt-v1`، کوکی‌های `HttpOnly` و محدودکننده تلاش ناموفق (Rate Limiting).

## 💻 راهنمای اجرای محلی (Local Setup)

### پیش‌نیازها:
- Node.js نسخه `22.13.0` به بالا (پروژه با Node 22+ سازگار است)
- ابزار `sqlite3` در خط فرمان

### روش ۱: نصب آسان و خودکار با ویزارد (پیشنهادی)
کافیست دستور زیر را اجرا کنید تا ویزارد تمام نیازمندی‌ها، پوشه‌ها، ساخت پایگاه‌داده SQLite، اجرای ۲۱ مایگریشن، تولید کلیدهای امنیتی و ساخت فایل `.env` را به صورت خودکار انجام دهد:
```bash
npm run setup
```

### روش ۲: راه‌اندازی دستی:
۱. **نصب وابستگی‌ها:**
```bash
npm install
```

۲. **تنظیم فایل متغیرهای محیطی:**
یک کپی از فایل `.dev.vars.example` به نام `.dev.vars` یا `.env` بسازید:
```bash
cp .dev.vars.example .dev.vars
```

۳. **اعمال مایگریشن‌های دیتابیس:**
```bash
node scripts/setup-wizard.mjs --non-interactive
```

۴. **اجرای سرور در محیط توسعه (با شبیه‌ساز کلادفلر):**
```bash
npm run dev
```

۵. **اجرای سرور پروداکشن Standalone (بدون نیاز به کلادفلر):**
```bash
npm run build
npm run server    # یا: node server.js
```

## 🗄 پایگاه‌داده و سیستم پشتیبان‌گیری چند لایه

پایگاه داده پروژه بر پایه **SQLite فیزیکی با حالت Write-Ahead Logging (WAL)** طراحی شده است:
- مسیر فایل پایگاه‌داده در سرور پروداکشن: `/home/donyagar/mashboard/data/dashboard.sqlite`
- **ایمنی در برابر Git:** کلیه فایل‌های `*.sqlite` داخل `.gitignore` قرار دارند؛ بنابراین اجرای `git pull` تحت هیچ شرایطی دیتابیس زنده را بازنویسی یا پاک نمی‌کند.
- **تراکنش‌های پایدار (ACID):** تغییرات بلافاصله روی لاگ دیسک نوشته شده و قطعی ناگهانی برق یا ری‌استارت سیستم موجب از بین رفتن داده‌ها نمی‌شود.

### 🛡️ ابزارهای پشتیبان‌گیری و بازیابی سریع:

| دستور | عملکرد |
| :--- | :--- |
| `npm run db:backup` | ایجاد اسنپ‌شات فیزیکی از SQLite به همراه خروجی تفکیک‌شده JSON برای تک‌تک برندها در پوشه `data/backups/` با چرخش خودکار ۵۰ نسخه اخیر |
| `npm run db:backup:git` | پشتیبان‌گیری هوشمند، به‌روزرسانی فایل‌های نسخه در `data/` و ارسال خودکار به ریپازیتوری پرایویت گیت‌هاب با تگ `[skip ci]` |
| `npm run db:restore:all` | بازیابی کامل و آنی داده‌های هر دو دفتر «دنیاگردی» و «نوآوران» |
| `npm run db:restore:novavaran` | بازیابی و فعال‌سازی مستقل دفتر «نوآوران راه سپید» (۸۰ روز بودجه، ۱۶۰ هزینه کانال و...) |
| `npm run db:restore` | بازیابی مستقل داده‌های پیش‌فرض دفتر دنیاگردی |
| `npm run brand:list` | مشاهده لیست تمام دفاتر و برندهای ثبت‌شده و وضعیت فعال/پیش‌نویس آن‌ها |
| `npm run brand:add` | افزودن تعاملی دفتر یا برند جدید به سیستم |

برای اعمال تغییرات جدید در اسکیما:
```bash
npx drizzle-kit generate
```

## 🌐 راهنمای استقرار در محیط پروداکشن و هاست

این پروژه دارای **معماری دوگانه** است؛ یعنی همزمان و بدون نیاز به تغییر کد، می‌تواند هم روی **Cloudflare** و هم روی **سرورهای لینوکس (VPS)** یا **هاست cPanel مجهز به Node.js** اجرا شود.

### گزینه ۱: استقرار روی سرور مجزا (VPS لینوکس با PM2)
۱. سورس‌کد را روی سرور دریافت کنید:
   ```bash
   git clone https://github.com/am333ni7y/ziarati-marketing-dashboard.git
   cd ziarati-marketing-dashboard
   npm install
   ```
۲. ویزارد نصب را اجرا کنید:
   ```bash
   npm run setup
   ```
۳. پروژه را بیلد و با **PM2** روشن کنید:
   ```bash
   npm run build
   pm2 start server.js --name "marketing-dashboard"
   pm2 save && pm2 startup
   ```
۴. برای Nginx ساب‌دامین خود (مثلاً `dashboard.domain.com`)، یک `proxy_pass http://127.0.0.1:3000;` قرار دهید و با `certbot` گواهی SSL رایگان بگیرید.

---

### گزینه ۲: استقرار روی هاست cPanel (مجهز به Setup Node.js App)
۱. پوشه پروژه را در هاست cPanel قرار دهید (یا از بخش **Git Versioning** آدرس ریپازیتوری را وارد و Clone کنید).
۲. در سی‌پنل به بخش **Setup Node.js App** بروید:
   - **Node.js version:** نسخه 22 یا 20
   - **Application mode:** `Production`
   - **Application root:** مسیر پوشه پروژه (مثلاً `marketing-dashboard`)
   - **Application startup file:** `server.js`
   - **Environment variables:** در صورت نیاز مقادیر `PORT`, `DASHBOARD_ADMIN_USER`, `DASHBOARD_ADMIN_PASSWORD_HASH` را وارد کنید (یا بگذارید از فایل `.env` بخواند).
۳. روی دکمه **Create** و سپس **Run NPM Install** کلیک کنید.
۴. دستور ویزارد نصب را در ترمینال cPanel یا اسکریپت اجرا کنید:
   ```bash
   node scripts/setup-wizard.mjs --non-interactive
   npm run build
   ```
۵. روی **Restart Application** در سی‌پنل کلیک کنید.

---

### گزینه ۳: استقرار ابری روی Cloudflare Workers / Pages
۱. دیتابیس D1 را در پنل کلادفلر بسازید: `npx wrangler d1 create DB`
۲. مایگریشن‌ها را به کلادفلر اعمال کنید: `npx wrangler d1 migrations apply DB --remote`
۳. باکت R2 را ایجاد کنید: `npx wrangler r2 bucket create BUCKET`
۴. متغیرهای محرمانه (`DASHBOARD_ADMIN_PASSWORD_HASH` و `GOOGLE_ADS_CREDENTIALS_ENCRYPTION_KEY`) را در بخش Cloudflare Worker Settings ست کنید.

## 🔄 استقرار خودکار پس از هر Push به گیت‌هاب (CI/CD)

### ۱. استقرار خودکار روی هاست cPanel:
این پروژه دارای فایل `.cpanel.yml` است. برای استقرار خودکار:
- در cPanel وارد بخش **Git™ Versioning** شوید.
- در تب **Manage**، گزینه **Push Deploy** یا آدرس **Deploy Webhook** را کپی کنید.
- در ریپازیتوری گیت‌هاب خود، به مسیر `Settings > Webhooks` رفته و URL وبهوک cPanel را اضافه کنید.
- از این پس با هر Push روی شاخه `main`، هاست cPanel شما خودکار کدهای جدید را Pull کرده، بیلد می‌زند و برنامه را Restart می‌کند!

### ۲. استقرار خودکار با GitHub Actions (سرورهای SSH / VPS):
یک پایپ‌لاین آماده در مسیر `.github/workflows/deploy.yml` قرار دارد.
کافیست در گیت‌هاب در بخش `Settings > Secrets and variables > Actions` متغیرهای زیر را ثبت کنید:
- `SSH_HOST`: آدرس آی‌پی سرور
- `SSH_USER`: نام کاربری SSH (مثلاً `root` یا `ubuntu`)
- `SSH_KEY`: کلید خصوصی SSH
- `APP_PATH`: مسیر پوشه پروژه در سرور (مثلاً `/var/www/dashboard`)
به محض هر Push به برنچ `main`، گیت‌هاب خودکار به سرور متصل شده، کدهای جدید را پیاده‌سازی و سرور را ری‌استارت می‌کند.

1. قبل از تغییرات، فایل `PROJECT_RULES.md`، مستند `docs/SYSTEM_GUIDE.md` و `CHANGELOG.md` را مطالعه کنید.
2. همواره اصل عدم صفرسازی داده‌ها در هنگام بروز خطا در منبع را رعایت کنید.

4. تمام تغییرات باید تست‌های پوششی در پوشه `tests/` را با موفقیت پاس کنند (`npm test`).
